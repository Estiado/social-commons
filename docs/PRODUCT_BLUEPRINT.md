# 产品蓝图与改进优先级

2026-10-21 已经逐项确认的文章导入、私人阅读、邮箱登录、Word/PDF 与近期精选范围，见 `READING_WORKSPACE.md`。该部分进入实施；下文其余推断仍是讨论建议。

本文件根据线上页面、路由、数据模型和交互推断产品方向。它供讨论与接手使用，不把推断当作用户已确认的全部需求。

## 我理解的网站目标

面向需要积累议论文论据、拓展思辨能力的学生，把“读到一点知识”变成“理解不同观点、记录证据并形成自己的表达”。首页的每日名句与通识是低门槛入口；群鉴提供多视角；专题和观澜连接作文话题；个人素材包完成带出处的输出。

产品的核心资产是**可靠的材料与有用的论证组织**。页面数量和文章总量只是辅助指标。

## 现状判断

| 已有基础 | 缺口与影响 |
| --- | --- |
| 具备日新、群鉴、撷英、专题、议论文、观澜六类内容 | 同时存在通用话题、热点话题、专题、分类四套组织方式，容易找不到或重复归类 |
| 群鉴列出不同叙述者和参考文献 | 还需要每项论断与具体证据对应，不能仅靠“有参考文献”代表每句话可信 |
| 名句有来源和解读 | 部分条目标注出处有争议；解读段落署名与原文边界需要逐条核验，列表也有重复与双重书名号 |
| 内置经典文章可直接读、外链时评可跳原文 | 内置文章的标题、摘编范围、日期和原文一致性需要检查，不宜仅凭文件注释判断内容性质 |
| 已能摘录、划线、组素材包并导出 | 摘录距离“可用论据”还差论点、适用边界、反例和自己的分析 |
| 支持匿名云端收藏和浏览器自定义条目 | 数据分在两套存储；用户可能误以为都已备份或能跨设备同步 |
| 首页/导航风格统一，阅读排版清楚 | 首页“最新时评”只读云端，数据库空时没有展示内置材料；手机图标入口需要更明确的文字或完整菜单 |

## 第一优先：可信与不丢数据

1. 建立来源字段：原文标题、作者、作品/媒体、具体页码或段落、原链接、最后核验日期、核验状态、摘录/转述/编辑解读类型。未经核验的材料不能默认为“权威”。
2. 先人工核验 20 条代表性材料作为内容基线；修改过的引文与争议归属单独标注。保留编辑解释的作者身份，不将编辑文字整段标成名家评论。
3. 审计 Supabase 权限和公开提取接口配额，明确编辑/管理员身份；配合迁移经典文章同步路径，再收紧当前宽松写入策略。
4. 提供正式账号或身份升级与备份：先说明哪些数据仅在本机，支持自定义词条 JSON 导出/导入，再做跨设备同步。

验收：任意一段导出的素材都能返回可靠原文；存储失败会提示；重新登录或换设备的数据恢复路径明确。

## 第二优先：完成写作闭环

统一使用稳定 `topicId`，名称可改、ID 不变，让通识、历史视角、文章、名句和个人摘录共用关联关系。热点可以作为标签，不必再成为另一套互不相通的分类。

素材包建议增加四个字段：**我的论点 → 原文证据 → 为什么能支持 → 适用边界/可能反驳**。可给出小任务：“选两种不同立场，写 150 字比较”，由用户自己完成分析，最终带引用导出。首页优先放“继续上次阅读”和“一次完整任务”的入口。

验收：用户能在 10 分钟内读两种观点、保存两条证据、写出一段自己的论证，并再次找到出处。此处是建议验收标准，尚无真实用户完成率数据。

## 第三优先：规模化内容与维护

- 云端文章做分页、全文检索和内容状态管理；全站搜索再接入文章及用户自己的材料，权限仍需隔离。
- 自动检查死链、重复引用和缺失来源，把核验队列交给维护者处理，不自动改写原文。
- 补编辑审核流程、发布预览与回滚记录。少量高质量内容先稳定，再扩大覆盖。
- 长列表在条目数和实际渲染指标需要时再考虑虚拟化；现阶段不引入大型搜索引擎或复杂服务拆分。

## 本轮已处理与暂未扩大的范围

本轮处理代码加载、搜索失效、结果定位、重复分类逻辑、保存错误、经典段落 ID 映射、素材包导出和 Cloudflare 接口适配，并建立维护文档。

尚未把所有存量内容逐条校对，也没有新建账号系统、重建数据库、实施权限迁移或改成自动生成作文产品。后续应先决定“只供自己学习、同学小范围使用、公开运营”中的主要场景，再安排权限与备份方案。
