# 架构与数据边界

## 分层

| 层 | 位置 | 只负责什么 |
| --- | --- | --- |
| 路由与页面 | `src/app.tsx`、`src/pages/` | 选择条目、组织交互；首页之外按需加载 |
| 阅读领域 | `src/features/reading/` | 统一模型、收藏、索引、素材包、导出 |
| 其他业务 | `src/features/essay/`、`auth/` | 个人素材和后续账号能力 |
| 内容与公共 UI | `src/data/`、`src/components/` | 内容目录、导航、通用控件 |
| 服务端 | `server/` | 受限抓取、无状态提取和限流 |
| 平台入口 | `functions/api/` | Cloudflare Request/Response 适配 |
| 数据库 | `supabase/` | 新表、RLS、精选元数据及种子 |

具体文件职责见 [目录导览](REPOSITORY_GUIDE.md)。

## 本机与云端

“浏览器内保存”与“本机开发服务器”是两件事。正式网站也可把私人文档保存到浏览器 IndexedDB，无需用户运行 CMD；开发地址只供维护者调试，两种域名的存储隔离。

站内正文和媒体正文统一为结构块，来源 HTML 不保存、不执行。标题、段落、引用、列表、图片与图注有稳定块 ID；划线使用内容版本及字符偏移。新私人正文不写入旧公共文章缓存。

文档和列表摘要独立存储；V2 摘录索引只存选中文字和出处。写入时同步替换该篇索引，过期和删除也在同一事务清理。列表不把所有全文拉入内存。标签页版本冲突必须报错，不覆盖其他标签页的修改。

素材包保存摘录引用、备注和顺序，不重复复制全文。缺失摘录会显示异常并阻止不完整的素材包导出；整库备份附关系和备注。

旧云端导入只读取当前已有身份的收藏和本人素材包，分页加载并核对所有错误；先校验、再追加本地数据。重复导入保留本机版本与备注，源表保持不变。它不等于新的跨设备账号系统。

## 算法与取舍

- 划线渲染按区间端点扫描，A 条重叠划线的分割为 O(A log A)，避免每段碎片重复扫描全部划线。
- 通识目录和搜索文本按模块预处理，输入只作线性过滤；没有宣称检索变成 O(1)。
- 目录去重使用 Set/Map；话题目录一次统计，关系推荐使用明确专题关联，避免按单个汉字猜测。
- 摘录页读取摘录索引，不扫描全部正文。旧库升级用游标逐篇处理，不清空重建用户数据。
- 导出依赖和中文字体按需加载；整库逐篇生成、约 25 MiB 分卷，避免同时展开所有 PDF。

## 服务端约束

抓取限制来源白名单、每次跳转、12 秒超时和 2 MiB HTML；图片代理限制媒体/CDN、4 MiB、光栅图片。拒绝私网、凭据 URL、任意代理和 SVG。提取为无状态服务，不使用 Supabase 服务端 Secret。

数据库和 SMTP 状态独立于部署成功。新私有表按正式账号 RLS 隔离；旧表权限仍须独立审计，不能用隐藏按钮代替鉴权。
