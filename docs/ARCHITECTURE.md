# 架构与数据边界

已确认的受众、产品定位与约束见根目录[PRODUCT.md](../PRODUCT.md)。Impeccable流程默认保存在`.impeccable/config.json`，它属于开发流程配置，不是页面实现；记录为暂停的待办不能自动实施。

## 分层

本轮显示层新增`navigationTaxonomy.ts`（不改来源/URL的导航归并）、`reading/hierarchy.ts`（线性显示树）、`ReadingHierarchy.tsx`（原生details与自动展开定位）和`RouteArrival.tsx`（路由起点/返回位置/标题/焦点）。显示树不持久化；收藏与Word/PDF继续读取完整原始块。旧群鉴/日新的扁平标题兼容明确限于站内目录，私人文章不推断标题父子关系。

知天下和每日简报的路由、日期规则及内容更新见[维护说明](WORLD_AND_BRIEFING.md)。两者使用`world`、`briefing`内容类型接入原阅读器；全站搜索只索引长期事件摘要，正文独立加载。弹窗先于首次指引；完整导航和指引断点统一为1280px。动效限于短入场并清理GSAP作用域，滚动保持原生。

知天下主文由`WorldChapter[]`顺序组织，章节与时间书签分工：`narrative`保存连续段落，`timeline`保存导航事实。`worldStoryBookmarks`用Map解析真实阅读块ID，检查缺失及重复关联，不为书签另渲染一套摘要。页面、收藏和Word/PDF保持同一篇文章；旧私人快照仍由内容版本区分。

`SiteMotion`由Layout按需加载，仅增强`main`中的标题和显式标记区域；每页共享IntersectionObserver和MutationObserver，新节点只扫描新增子树。路由切换、弹窗暂停和减少动态效果变化时释放作用域、观察器和临时集合。原有`ReadingEntrance`标明局部动效边界，避免重复入场；正文段落和可编辑区不做位移。详见[阅读动效](READING_MOTION.md)。

## 本机与云端

编辑稿在构建期解析为`.artifacts/editorial/`模块，不在浏览器解析整份Markdown。标记内只有文本，不执行代码、HTML或front matter。构建前检查实际TypeScript字段引用与总稿编号一致；缺失、重复和孤立编号失败。原诗、引语和出处数据仍在`src/data`，内容迁移不改写读者私人存储。

“浏览器内保存”与“本机开发服务器”是两件事。正式网站也可把私人文档保存到浏览器 IndexedDB，无需用户运行 CMD；开发地址只供维护者调试，两种域名的存储隔离。

站内正文和媒体正文统一为结构块，来源 HTML 不保存、不执行。标题、段落、引用、列表、图片与图注有稳定块 ID；划线使用内容版本及字符偏移。新私人正文不写入旧公共文章缓存。

文档和列表摘要独立存储；V2 摘录索引只存选中文字和出处。写入时同步替换该篇索引，过期和删除也在同一事务清理。列表不把所有全文拉入内存。标签页版本冲突必须报错，不覆盖其他标签页的修改。

IndexedDB V3 原位新增 `drafts` 和 `draftSummaries`，保留旧文档、索引与期限。文稿是所选内容的独立快照，编辑不覆盖来源与划线。旧素材包转为文稿，保留原关系备份；缺失的旧摘录显示编号与待恢复提示，备注保留。文稿自动保存串行写入并检查 revision，冲突或容量不足时保留编辑区内容供下载，禁止静默覆盖。

编辑器仅在 `/reading/write/:id` 加载；Tiptap JSON 转换为经过 Zod 校验的文本块与格式范围。格式范围有序、不重叠；正文长度、块数、图片数与 URL 协议受合同约束。DOCX/PDF 共用格式片段，选材只加载已选正文；摘要列表不加载全部正文。

IndexedDB V4增加 `searchEntries`，只保留标题、来源、段落ID和纯文本；写入与原件同事务。`searchIndex.ts`只负责命中和文字范围，`searchRepository.ts`逐条游标读取并支持取消。查询是正文总长度的线性扫描，额外内存为当前条目与命中摘要，不是倒排索引或O(1)检索。查询与匹配状态按请求区分，旧异步结果不能覆盖新查询；正文标记只用于显示，文稿选中只改变编辑器选区，均不改原文字与划线。

观澜按话题归类、以事件为阅读单元：`guanlan/catalogue.ts`提供轻量入口，正文按事件动态加载，`eventDocument.ts`适配统一文章模型。相关名句和通识展开后初始化阅读器。公共精选元数据仍来自`curatedCommentaries.ts`；原话题资料保留。

私人关联只写本浏览器记录的`topicIds`和可选`eventIds`，同一事务更新摘要、摘录、搜索索引；不改变正文与标注偏移。导入后返回具体事件的私人材料区。两种备份格式兼容可选eventIds，无需数据库升级。公共目录不查询私人全文；SQL种子是可选服务端副本，更新文件不代表已经执行线上SQL。细节见[事件维护](GUANLAN_EVENTS.md)。

旧云端导入只读取当前已有身份的收藏和本人素材包，分页加载并核对所有错误；先校验、再追加本地数据。重复导入保留本机版本与备注，源表保持不变。它不等于新的跨设备账号系统。

## 算法与取舍

- 划线渲染按区间端点扫描，A 条重叠划线的分割为 O(A log A)，避免每段碎片重复扫描全部划线。
- 通识目录和搜索文本按模块预处理，输入只作线性过滤；没有宣称检索变成 O(1)。
- 目录去重使用 Set/Map；话题目录一次统计，关系推荐使用明确专题关联，避免按单个汉字猜测。
- 摘录页读取摘录索引，不扫描全部正文。旧库升级用游标逐篇处理，不清空重建用户数据。
- 导出依赖和中文字体按需加载；整库逐篇生成、约 25 MiB 分卷，避免同时展开所有 PDF。

## 服务端约束

抓取限制来源白名单、每次跳转、12 秒超时和 2 MiB HTML；图片代理限制媒体/CDN、4 MiB、光栅图片。拒绝私网、凭据 URL、任意代理和 SVG。提取为无状态服务，不使用 Supabase 服务端 Secret。

数据库和 SMTP 状态独立于部署成功。新私有表按正式账号 RLS 隔离；旧表采用202610230001增量权限修复，实际执行状态见验证记录，不能用隐藏按钮代替鉴权。

## 本轮维护入口

- `history/` 按事件拆分，`readings.ts` 为文献清单；对应视角通过 `readingId` 附电子版，文件大小/散列由清单检查。
- `references.ts` 保存引用的可见题名和链接格式范围，`textSegments.ts` 合并富文本与收藏划线边界。新快照及新文稿显示题名，旧保存文本不重写。
- `backup.ts` 的本机备份用只读事务、游标逐条序列化并限制大小；恢复先完整校验，再在一个事务中追加文档/摘要/摘录/文稿。重复ID或迁移来源跳过，不覆盖已有记录。
- `ReadingBackupControls` 处理文件选择和状态，底层存储/校验不依赖页面；`feedback/report.ts` 是纯报告函数，不收集文章、身份或设备信息。
- `personalBackup.ts`组合阅读备份与`essay/personalData.ts`的显式白名单；不遍历/打包未知localStorage，不含认证信息或反馈。新格式不改旧阅读模型，恢复先完整校验，再按存储边界补缺；局部失败可安全重试。
- `feedback/draft.ts`处理本地草稿合同、原始快照比较和待确认提交编号；`navigation.ts`是导航共用的小模块，布局不为生成链接而加载表单校验代码。草稿不等于在线提交。
- 指引步骤和动画组件分离，布局只保留首次判断及按需入口。具体路线与可访问性约束见[GUIDED_TOUR.md](GUIDED_TOUR.md)。
