# 群鉴条目规范

这是用户确认的内容规则。新增或修改历史词条时按此执行。

## 一条词条的结构

1. **事件概述**：让初次接触的读者知道时间、地点、参与者、经过及后续影响。优先参考博物馆、科普著作、正式出版物和可信机构的介绍。允许站方做有依据的事实概述，提供具体来源。
2. **多方视角**：来自真实已发表的论文、期刊、媒体文章、演讲稿、书信、回忆或著作。每个视角有作者/身份、论点背景、短摘录、准确出处与可定位的章节或页码。不同视角要有实质差异，不能把同一观点改写三遍。
3. **电子文献**：放在对应视角下方。可合法再分发且实际下载、检查过的文件才放 `public/readings/history/`；其他公开电子版保留直接链接。可访问、可下载不自动等于可整本镜像。

不把课堂讨论、备课练习、站方自拟问题当成历史人物观点。没有核验的论文不补造作者、摘要、DOI 或下载链接。无法核实的旧条目保留在 Git 历史，不能继续包装为已核验文献。

## 引文与版本

- `quote` 为短摘录的中文呈现，译文通过 `translated` 标识；`original` 保留对应原文，`locator` 指明位置。
- 描述段用于交代背景与概括观点，不加引号冒充作者原话。中文原文无需再标“节译”。
- 节录不得隐去改变原意的上下文。类似 Wamsutta 的文字要说明是准备稿，不能称为已在当年庆典发表的演说。
- 电子版记录译者、出版版本、来源、文件大小与 SHA-256。原许可说明保留在文件中；编辑流程和核验日期放维护文件，不堆在读者正文中。

## 模块

事件按题目拆分到 `src/data/history/`，`index.ts` 汇总；`src/data/events.ts` 保留稳定入口。文献清单在 `readings.ts`，站内文件完整性清单在 `public/readings/history/manifest.json`。

正文、出处、文献标题共享阅读模型，可收藏、划线、编排和导出。更新站内资料生成新快照，不重写读者已保存的旧文档或划线偏移。
