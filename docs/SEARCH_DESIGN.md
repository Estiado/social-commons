# 全站搜索设计与维护

本轮范围：六个公共内容栏目。读者可能每周只有一个早上浏览，因此先帮助他判断“哪一条值得打开”，再进入原有阅读、收藏和导出流程。

## 实施前的设计决定

- 首页增加可见搜索条，桌面导航明确写“搜索”，保留 Ctrl / Command + K。沿用弹窗以便从任何文章搜索后继续阅读，返回不丢掉原页。
- 面板从窄命令列表扩大为阅读检索界面：输入框 → 栏目及命中数 → 可展开的分类/标签/来源 → 结果列表。手机使用动态视口，只有结果区域滚动；筛选默认收起。
- 每条显示栏目、标题、所属分类、来源、约两行摘要、少量标签。命中正文时优先截取匹配附近文字，避免标题命中后仍不知道内容。点击标题所在整行直接进入条目。
- 六栏目共用一次检索结果后计数，筛选发生在截取展示页之前，避免前30条占满后找不到其他栏目。多词同时匹配，标题命中优先，正文补充；排序稳定。逐批展示，不将几百条DOM同时放进弹窗。
- 纸色、墨色、朱色与原字体保留。输入及筛选使用站内无衬线字体，标题沿用衬线字体。列表用间距与细线区分，不放彩色图标、嵌套卡片或装饰背景。

版面：

```text
全站搜索                         关闭
[ 搜索事件、名句、概念或作者       ]
全部(…) 观澜(…) 知天下(…) 日新(…) …
筛选：分类 / 标签 / 来源      清除筛选
找到 … 条
栏目与分类                     来源
完整标题
命中附近的简短摘要，关键词醒目标记
标签 · 标签
```

采用 Frontend Design 的任务导向排版，以及 Impeccable Operate 的熟悉控件、状态和克制动效。Taste 已抽取 workspace 方向，但其中“问候语+统计面板”不适合材料检索；按真实任务保留其低彩度、无嵌套表面原则，改为搜索与列表。素材库中的 Lenis、Vanta、React Bits 不解决本次检索问题，不引入依赖。

## 实现边界

`src/lib/search.ts`维护归一化、多词匹配、排序和摘要；`src/data/searchIndex.ts`建一次公开索引；`GlobalSearch.tsx`仅维护输入和筛选状态。知天下和观澜只使用轻量目录，不预载每篇长文。阅读空间私有文稿仍在阅读空间自己的搜索中。

标签和来源为内容已有元数据，不能让界面生成不存在的媒体归属。观澜、知天下目录通过可选的sourceNames数组登记媒体或机构短名，来源选项逐一展开，选中一个机构即可匹配包含它的事件。目录保持轻量，运行时不为筛选预载长文。缺少作者时显示资料名称，不将本站摘要当成原作者原话。数据更新自动进入搜索；后台和私人正文不会进入此索引。

查询不发送服务端、不保存搜索历史。高亮通过React文本节点及mark元素呈现，不拼HTML。查询长度与词数受限，结果按批展开，标签可显示完整命名；空结果有清空筛选及替换词提示。
