## 当前目标与约定

2026-10-22 调整：用户明确暂缓邮件系统，先本机内测。新阅读功能默认不要求登录，文章与摘录可长期存于本浏览器；`VITE_READING_CLOUD_ENABLED=false`。固定端口 5180，双击根目录 `启动本机内测.cmd`。下文的邮箱登录和跨设备实现是准备好的后续能力，不代表真实邮件验收已完成。

用户已批准分阶段开发私人阅读空间，详见 `READING_WORKSPACE.md`。保留社科通识品牌与旧阅读内容。新过程文件、缓存、测试截图和构建均在 D 盘；每轮交付前检查、提交、推送并核验 GitHub SHA，禁止强推。

先按 `ARCHITECTURE.md` 定位模块，不读取整站数据。页面只组织交互；解析、存储、权限和导出有独立边界。注释说明原因与约束。不要在通用 UI 模板中堆业务逻辑。

## 已实现

- 旧阅读内容、中文搜索、专题定位、素材包整理与按需加载的重构已保留。
- `/reading/import` 支持媒体链接及正文粘贴、元信息修正和预览；标题层级、段落、引用、列表、插图和图注统一排版。
- 提取改为无状态服务，不需登录或 Supabase 服务端密钥，不向公共文章表写全文。抓取和图片代理检查来源、每次跳转、流大小、超时及速率。
- `/reading` 读取本浏览器七天临时摘要和正式账号云端摘要；`/reading/:id` 按篇读取。重复 URL 只在本人空间去重。
- 段落收藏、跨段划线、Word/PDF 正文和摘录导出、整库 ZIP 分卷。当前点击保存或收藏即可在本机长期保留；邮箱登录和云端同步等待后续验收。RLS 按用户隔离，版本检查防止无声覆盖。
- 首批 13 篇近期精选只有公开元数据、原文链接、本站推荐理由及双用途教学标签。个人全文和摘录不公开；用户推荐需要维护者审核。
- Word/PDF 库和中文字体点击导出时才加载；PDF 嵌入完整静态中文字体以修复实际渲染缺字。

## 验证与运行

Windows 使用 `scripts/dev.ps1 dev` / `scripts/dev.ps1 check`。`npm run dev` 直接调用与生产相同的 API 处理器，不使用模拟提取。产物在 `.artifacts/` 与 `dist/`，不进 Git。

`npm run check` 包含类型、ESLint、38 项回归、独立 PostgreSQL RLS、生产构建、两个函数打包与真实 Word/PDF 文件生成。PDF 六页已逐页视觉核验；Word 已校验可编辑 OOXML、标题样式和超链接，当前 Windows 无 LibreOffice，尚未完成 Word 版式渲染验收。详细事实与生产状态见 `VERIFICATION.md`。

## 部署与后续边界

- 新数据库表和精选种子脚本、邮箱模板、SMTP、旧匿名账号绑定说明见 `READING_WORKSPACE.md`；生产执行状态只以验证记录为准。
- 提取不再依赖旧的 `SUPABASE_SERVICE_ROLE_KEY`。浏览器仅使用公开客户端 key，不能把服务端 Secret 放入 `VITE_*`。
- 未配置数据库时仍可导入、临时阅读和导出；云端功能明确提示未就绪。SMTP 发信成功、真实账号保存与第二账号隔离必须单独验收。
- Cloudflare 未绑定分布式限流时，只有每实例内的有限窗口，不能宣传全局配额。
- 南方周末可能只公开部分正文；公众号和动态网页可能无法抓取，使用粘贴入口并核对完整性。
- 新私人摘录保存在阅读文章内，旧段落库和素材包继续可用，目前两套摘录尚未合并。云端目录目前只列最近 100 篇。
- 旧文章/段落/素材包表的线上权限、经典段落并发补齐和原子排序仍需独立审计；新阅读空间的测试不能代替旧表审计。

不要以页面显示“管理员”推断权限；不要将模拟来源或独立 PGlite 的结果写成生产 Supabase 验收。
