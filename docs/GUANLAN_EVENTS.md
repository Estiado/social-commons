# 观澜：话题下按事件阅读

更新：2026-10-25。用户确认的结构是“话题归类 → 事件精读 → 附属资料”。时评、研究、名句和通识是事件的组成材料，不再分别充当观澜主入口。首批三个完整案例为非遗短视频、职场AI、学术酒吧；其他话题先保留既有资料，不伪造空事件凑数。

## 页面与内容

- `/guanlan`：紧凑的话题入口、事件列表；完整50篇近期目录和经典文章保留在展开区。
- `/guanlan/topics/:id`：当前话题的事件优先，原有说明、通识、名句、私人时评和媒体目录继续保留。旧`/topics/:id`入口不失效。
- `/guanlan/events/:id`：新闻回放、深度背景、多维立意、思辨翻转、媒体评论与研究。相关通识和名句在页内展开，共用收藏与划线；仍可打开独立页面。
- 同一事件可以属于多个话题，正文与规范地址只有一份。搜索直接进入事件，不仅返回话题总页。

## 文件职责

| 文件 | 用途 |
| --- | --- |
| `src/data/guanlan/catalogue.ts` | 首页、话题、搜索使用的轻量标题与关联元数据 |
| `src/data/guanlan/types.ts` | 事件、视角、出处的内容合同 |
| `src/data/guanlan/index.ts` | 按ID加载对应正文，未知或原型属性不返回模块 |
| `heritage.ts`、`aiAtWork.ts`、`academicBars.ts` | 各事件的正文和完整书目 |
| `src/features/guanlan/eventDocument.ts` | 转换成统一文章块；题名超链接、视角下电子版、编辑署名 |
| `EventCatalogue.tsx` | 事件查询及列表 |
| `EventSources.tsx` | 按媒体或期刊筛选原文与电子文献，不修改已存正文 |
| `EventRelatedReadings.tsx` | 展开后才初始化通识、名句阅读器 |
| `src/pages/GuanlanEventPage/` | 页面组织、目录锚点、异步加载及导入返回位置 |

事件页不另写一套划线、编辑、Word/PDF和数据库逻辑，统一调用`ContentReader`。公共内容调整沿用快照机制，不覆盖用户旧版本及划线。

## 个人材料关联

`ReadingAssociations`替代原`TopicReading`，同时服务话题和事件。导入URL携带`event`，确认后将文章关联到该事件并返回`#my-event-materials`；在异步事件加载后再滚动到个人材料区。来源不支持链接提取时使用`importMode: 'paste'`，保留来源链接而不扩展服务端白名单。

本浏览器`ReadingRecord.eventIds`与`topicIds`并存，关联自动去重，最多各100项。读取当前版本后，在同一IndexedDB事务更新文档、摘要、摘录及搜索索引；保留正文、内容版本和标注偏移。关联后长期保存，但仍受清理浏览器数据影响，不代表云同步。

旧阅读v1和统一个人v1备份都可继续使用；`eventIds`是可选字段，无须升级V4数据库版本。新备份恢复时保留事件关系，重复恢复不覆盖已有修改。没有向Supabase新增事件私有表，没有改变生产权限。

## 添加一个事件

1. 先找到能讲清具体事情的报道，以及可形成不同观察角度的真实著述，核对作者、日期和正文/摘要范围。
2. 在`catalogue.ts`增加稳定ID、标题、简述、问题、时间说明、话题ID和关键词。`sortDate`用于排序，必须与明确资料日期对应，不能充当虚构发生日期。
3. 建独立正文模块，补足回放、背景、三个视角和思辨翻转，所有引用的`sourceIds`必须存在。视角可来自不同时期研究，不把后出的研究发表日写成事件起点。
4. 来源写题名、作者、媒体/期刊、实际日期及URL。摘录原话只在`quote`中填写核实的文字和说话者；资料概述不加伪造引号。编辑比较与追问由“社科通识编辑”署名。
5. 有电子版时使用可读的题名链接，紧随相应视角。可下载不等于有再分发许可，未经核定不复制进`public/`。第三方公开馆藏与期刊出版站要分清。
6. 在`index.ts`登记加载器，更新来源台账；运行`tests/guanlanEvents.test.ts`与完整检查，核对手机长标题、段落收藏、导入返回和备份。

维护过程、核验范围和编辑要求写在文档与数据合同里，读者页面只呈现内容、作者和具体出处。不加入课堂讨论、备课任务或无出处的“媒体金句”。
