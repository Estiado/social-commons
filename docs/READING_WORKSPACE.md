# 私人阅读空间：开发与运维

本方案由用户于 2026-10-21 确认。公开导入工具与近期精选目录；导入全文和摘录只属于导入者。首批精选以近期热点为主，最多 50 篇，可少于此数。保留社科通识品牌与阅读风格。

## 工程约定

### 2026-10-22 统一入口调整

日新、名句、历史、经典时评、专题和素材正文共用阅读模型与选区组件；文章、全局摘录和素材包统一到 `/reading`。旧路径重定向，旧云端原件不删除。IndexedDB V2 游标补齐摘录索引，保留 V1 文章和收藏；文档、摘要和索引同事务更新。素材编辑后以正文摘要生成独立阅读版本，不覆盖旧划线。旧资料导入只用当前已有身份，分页读取且核对每个错误；重复导入保留本机名称、顺序和备注，并保留新追加条目的原备注。

日常入口是 Cloudflare 正式网站。“保存在当前浏览器”不要求运行开发服务器。旧根目录 CMD 已归到开发工具目录，维护者预览与正式站的浏览器存储隔离。

### 2026-10-22 本机内测调整（优先于原上线方案）

用户暂缓邮件系统。`VITE_READING_CLOUD_ENABLED` 默认 false：免登录提取、阅读、段落/跨段划线收藏、全文及整库导出均可用。导入先保留七天；点击“保存到本机”或收藏后，IndexedDB 的 expiresAt 置空，在当前浏览器长期保留。localRevision 在事务内检查，防止陈旧标签页覆盖摘录。清理浏览器数据仍会移除文章，需另行备份。

日常使用正式网站，无需启动 CMD。维护者开发预览固定 `http://127.0.0.1:5180`，可用 `scripts/windows/开发预览.cmd` 或 `scripts/dev.ps1 dev`；重复启动会复用本站现有服务，不结束其他进程。正式网站与开发预览使用不同浏览器存储。脚本使用已有 Node，临时文件和缓存位于 D 盘，不搬浏览器配置或修改系统隔离。

访问受限媒体标为 partial，预览只允许粘贴完整正文或显式保存可见节选；阅读及导出均标节选。导入者核对完整后可替换本机旧节选；云端替换还须确认旧版本摘录清除，并检查 revision。提取成功不等于全文完整。

整库导出逐篇处理本机文章。未来账号启用后游标分页读取全部云端摘要，不受最近 100 篇列表限制。Word/PDF/JSON 使用 ZIP，约 25 MiB 分卷、单篇 40 MiB 上限。每篇附结构及摘录 JSON，最后一卷有完整成功/缺图/失败清单；取消后已下载分卷保留，浏览器可能需要允许多文件下载。

素材区分读者本地增改与站方公开示例；名句来源和发布权限见 `CONTENT_POLICY.md`。相关卡片链接至 `/daily/:id`、`/quotes/:id` 独立页面，旧查询参数入口自动跳转。

已执行新增阅读表和示例/编辑名单迁移；线上有 13 条精选、2 条示例，5 张新增表均开启 RLS，编辑名单为空。SMTP 未配置，平台锁定模板；用户已明确延期，未输入或保存凭证。未来先配置发信、三个 OTP 模板和身份升级，完成真实账号验收后再启用云端功能。

- 页面组织交互，领域模块处理文章、存储和导出。业务代码不进入 `components/ui`。
- URL 导入和粘贴导入共用结构化文章；不保存或执行来源 HTML。数据在接口、粘贴和云端读取边界校验。
- 正文按有序块保存：标题、段落、引用、列表项、图片及图注。块 ID 与内容版本稳定；划线记录块内起止偏移，支持跨段选择。
- 注释解释特殊来源规则、权限边界和失败恢复原因。变量、函数名表达实际业务。
- 有限的纯函数和明确的模块边界；不为单次调用建立空泛的框架。数据库错误必须处理，成功提示必须对应已完成的写入。
- 新业务模块按 `.prettierrc.json` 统一排版；使用 `npm run format:reading`，保持多行条件、清楚的 JSX 层级和可阅读的函数体。排版工具不替代类型、权限与行为检查。
- 目录只读取摘要；正文按篇打开；导出依赖及中文字体在导出时加载。用索引处理去重和用户列表，避免全站正文常驻内存。
- 变更附带必要的回归验证，检查通过后提交与推送，核验远端 SHA。新过程文件和缓存放 D 盘。

## 存储与权限

访客：正文保存在当前来源域名的 IndexedDB，保留期限从确认导入起计算七天，重复导入不延长原期限。读取和列表访问时清除过期记录；打开中的文章也检查期限。浏览器可提前清理本机存储，换域名或清理浏览器数据不构成云端备份。

正式账号：`reading_documents` 的一行包含完整结构与摘录，通过一次写入共同提交。RLS 同时检查 `owner_id = auth.uid()` 与非匿名身份。`revision` 是乐观锁，旧设备的保存不会无声覆盖另一设备的新收藏。新私人文章不进入原有 `articles` 公共缓存。

云端保存确认成功后才移除访客副本。相同原文链接只在本人的账号内去重；已有不同版本且带摘录时提示用户打开已有版本，避免错误迁移位置。

`reading_submissions` 只包含标题、来源、URL 和推荐理由，不含全文与个人摘录。普通账号只能提交 pending 状态；维护者在 Supabase 管理端审核元数据后更新公共目录。`reading_catalogue` 只允许访客读取 published 项，普通账号没有修改权限。

旧匿名收藏仍在原表。新邮箱首次绑定优先升级当前匿名身份，保留原用户 ID；需要 Supabase 启用 manual linking。登录已有邮箱账号不自动合并另一个匿名身份，界面提示先导出旧收藏。不得以更新前端 user_id 冒充已完成安全的数据迁移。

## 部署步骤

1. 使用 `scripts/dev.ps1 check` 执行检查；`npm run dev` 也调用真实的共享接口处理器。
2. 在现有 Supabase 项目执行 `supabase/migrations/202610210001_reading_workspace.sql`。这是新增表的事务，不删除旧文章或收藏。执行前核对目标项目与已有表名。
3. 运行 `npm run seed:catalogue`，人工复核 `supabase/seeds/reading_catalogue.sql`，再在同一项目执行。只写入公共元数据。
4. Cloudflare 构建继续使用 `npm run build`，输出 `dist/client`；构建配置保留 `VITE_SUPABASE_URL` 与公开 anon/publishable key。提取无需 service role key。
5. Supabase Auth 启用邮箱登录；正式公众发信配置自有 SMTP。登录确认邮件和邮件变更模板均需包含 `{{ .Token }}`，否则用户收到的是链接而非界面需要的验证码。首次匿名升级需要 manual linking。核对站点 URL 与允许的回跳 URL。
6. 可配置 `EXTRACTION_RATE_LIMITER` 的 Cloudflare 分布式限流绑定；未配置时只有每个实例内的有限窗口（提取 10 次/分钟、图片 120 次/分钟），不能声称具有全局配额。Netlify 仅保留旧提取函数兼容，新的图片代理以 Cloudflare 为验收平台。
7. 核验生产静态页面、提取、图片、正式账号保存、第二账号隔离与另一设备同步。部署成功不代表数据库迁移和邮件服务已就绪。

## 媒体适配与精选维护

新增来源先核验真实正文容器、署名、日期、相对图片与图注，再增加白名单和适配器。人民日报模板存在旧日期和版次冒充作者的元信息，当前以可见署名为准。澎湃使用会变动的 CSS 类名，按稳定词段匹配。南方周末可能只向未登录访客展示部分正文；保留明确核对提示。公众号与动态网页可能抓取失败，粘贴导入是正式入口。

首批 13 条（2026-10-21 核验）包含人民日报、人民网、浙江宣传、澎湃新闻、南方周末、新周刊。新周刊条目保留官方公众号地址，署名和日期另通过作者媒体在虎嗅的刊载页核验；不把公众号可提取性标成已通过。推荐理由由本站编辑撰写，原文作者字段独立展示。最近 30 天为默认范围，过期项转往期视图，不会冒充最新内容。

更新流程：编辑数据文件 → 核验原页标题、署名、日期、链接 → 运行 seed 生成脚本 → 检查变更 → 数据库写入 reviewed 元数据 → Git 提交。用户推荐由维护者人工审核后进入此流程，不自动发布全文。

## 导出与字体

Word 使用可编辑文本、标题样式和内嵌图片。PDF 使用真实文本与分页，不能用整页截图代替。两种格式读取同一文档，保留作者、媒体、日期、原文地址及导入完整性提示。图片失败时保留缺图说明与原图地址，并在界面提示。

中文字体来自 Google Fonts 的 Noto Sans SC，许可证在 `public/fonts/OFL.txt`。源为 `google/fonts/ofl/notosanssc/NotoSansSC[wght].ttf`，通过 `scripts/prepare-pdf-font.py` 固定为 400 字重。字体只在 PDF 导出时请求。fontkit 对该字体进行子集化在实际渲染中会丢失字形，因此嵌入完整静态 TrueType；PDF 基础体积约 6.5 MB，是本版为跨阅读器正确显示作出的明确取舍。

## 故障排查与回滚

- “阅读空间尚未初始化”：核对 Supabase 项目与迁移；本机文章继续保留。
- 邮件只发给团队成员或发信受限：检查正式 SMTP、模板与 Auth 限额，界面错误不能伪装发送成功。
- 正文只有摘要：核对原站访问范围，改用正文粘贴，保留原文地址。
- 图片失败：检查来源/CDN 白名单、HTTP 状态、4 MiB 上限和来源地址；不放开任意 URL 代理。
- 跨设备冲突：重新打开服务器已保存版本后再收藏，不强制覆盖。
- 开发监听锁定：`.artifacts` 与 `dist` 已排除在 Vite 文件监听外。
- 前端回滚：Cloudflare 选择上一份成功部署。新增表无需删除；回滚前导出新私人数据，不用旧初始化 SQL 重建整库。

## 验证边界

`npm run check` 包含类型检查、ESLint、单元/行为回归、独立 PGlite PostgreSQL RLS 验证、生产构建、函数打包及真实 Word/PDF 生成。PGlite 不代表生产 Supabase 验收；文件生成和文字可提取也不代表版式已视觉验收。真实生产与视觉检查结果另记于 `docs/VERIFICATION.md`。
