# 只改一份文本，更新站内编辑内容

你要编辑的文件是 **[content/站内编辑稿.md](../content/站内编辑稿.md)**。目前集中34组、620处文字，按观澜、日新、撷英、群鉴、素材和话题分组。可以搜索文章标题或条目编号，不必打开程序文件寻找段落。

## 在GitHub修改

1. 打开仓库的`content`目录，进入`站内编辑稿.md`，点击铅笔编辑。
2. 搜索要改的标题，修改`<!-- copy: … -->`与`<!-- /copy -->`中间的文字。两行编号标记保留原样。
3. 段落之间留一空行。这里录入普通文字，不需要写引号、逗号、JSON或代码；不要把整个文件重新粘贴进某一个标记里。
4. 提交修改。站长按仓库权限提交到main；同学通过分支和PR，审核后合并。
5. 等GitHub检查和Cloudflare发布成功，再刷新正式网站。无需打开本机CMD，也无需执行SQL。

只修改本地文件还不会更新正式站，需要提交并推送GitHub。也可以在本地保存后，让维护者或当前开发助手完成检查与同步。

## 哪些内容在这里

- 观澜事件标题、简介、问题、回放、背景、立意、编辑反思及原文资料提要。
- 日新解释、简介；资料台账生成的素材说明会共用同一份文字。
- 撷英的赏析转述、作品背景和版本说明。
- 群鉴的事件概述、视角说明。
- 议论文素材说明、站方素材正文和使用提示；媒体推荐说明、话题介绍等。

它们既包括本站叙述，也包括有归因的资料摘要，不能全部当作原创观点。原作者诗文、直接引语、作者与书目信息、来源URL、标签及关联ID仍放在`src/data/`。经典原文和媒体原句没有搬入编辑稿，也不因这次整理而改写。导航、按钮与错误提示属于界面代码，不在这份正文稿中。

修改资料摘要时，应对照它所附的原文，保留作者主张的范围。编辑比较与假设不能改成研究者的原话，也不能在只有摘要时补写未见过的样本或结论。改错了文献作者、链接或关联编号，需要维护者同时修改相应数据文件。

`###`标题方便查找；页面显示的正文以标记中间的文字为准。部分旧字段为兼容保留，是否显示仍遵守原有核验状态；改写文字不会自动解除未核验来源的发布限制。

## 工程师接手

`scripts/editorial-content.ts`将总稿校验后生成到D盘仓库内的`.artifacts/editorial/`，按原内容模块拆分。页面只导入所需模块，不在浏览器里解析或下载整份总稿。生成文件不提交GitHub，也不手工编辑；它们可由总稿重新产生。

`npm run dev/build/typecheck/test`及两个seed命令的前置步骤会生成内容；Vite也在启动构建时生成。本地预览监听总稿修改后重启开发服务，使页面读取新文字。直接运行某个依赖内容数据的Node工具前，先运行`npm run content:sync`。Node.js使用项目约定的24版本。

校验使用TypeScript语法树读取实际字段引用，支持自动排版后的多行代码，不把注释示例当作正文编号。重复编号、缺失标记、整组删除、空正文、没有登记的编号或超限文本会报错；所有编号校验完成后才写生成文件。未变化的模块不重写。

需要新增条目时，除了总稿，还要在`src/data`登记结构、来源和ID；不能只在文末随意添加一组标记。阅读器和导出仍使用统一文章模型，编辑稿更新会生成新的公共内容快照，不覆盖读者已保存的旧文章、划线或文稿。

本轮按humanizer-zh修订观澜三篇：补足实际信息，去掉重复的铺垫和编写过程说明，保留归因、研究对象和限制。其余已迁移内容保持原文；这次没有把全部旧内容重新核验或重写。
